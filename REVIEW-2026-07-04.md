## Blocking (fix before trusting core folding globally)

1. **Budget guarantee inverts under real pressure** (`policy/budget.ts:121-153`,
   `policy/keel.ts:167-170`). Hard-cap floor stages 2/3 book savings for group/drop runs that
   `applyPlan` then (correctly) refuses, because tool_call/tool_result pairs make whole-message
   removal impossible in ordinary tool-heavy sessions — and the regroup strip cancels the folds
   stage 1 would have done. Reproduced: 120 read-exchanges, cap 6000 → **46,069 tokens shipped
   (7.7× cap)** while telemetry reports `live_tokens: 5931, over_budget: false, dropped: 94`
   (0 messages actually removed). Re-plans and re-fails every turn. Fix: floor must only build
   runs whose messages are provably whole-removable, or feed applyPlan's actual result back
   into the projection/telemetry.

2. **Skeletonizer crash, uncaught on the whole fold path** (`skeleton/skeletonize.ts:239-264`;
   no try/catch in `ladder.ts:trySkeleton`, `keel.ts:route`, or the `context` hook).
   Unterminated quote to EOF → mask one char short of source → `TypeError` on the parallel
   index walk. Triggers: most real Rust files (odd count of `'lifetime` apostrophes) and any
   truncated read (`head -n 50 foo.ts`) that cuts a string. Willow's harness catches the throw
   and ships the unfolded array, so the session survives — but folding silently dies every
   turn from then on. Fix: backfill the mask hole + length-assert with generic fallback, and
   wrap `trySkeleton` fail-open like the sibling hooks.

3. **Catastrophic regex backtracking = synchronous hang** (`skeleton/classify.ts:499-502`,
   `stripTrailingTruncation`). Measured: 1094ms at 2k trailing whitespace chars, 8637ms at 4k,
   ~O(k³) — a blank-padded flood hangs the model call for minutes+. A hang, not a throw: the
   harness try/catch cannot contain it. Fix: trim trailing `[\s.…]` manually, then anchor a
   short regex on the last ~40 chars.

4. **L0 kill switch not honored on resume** (`adapters/pi/index.ts:106-119`). `session_start`
   restore never consults `gateConfigFromEnv().enabled`; with `CONTEXTFOLD_L0=0` a resumed
   session still substitutes pointers (with teaching text suppressed). Violates DESIGN §6a
   "unset/0 inert".

5. **`recall` re-flood path** (`adapters/pi/store.ts:573-583`). `lines=` and whole-`recall`
   are uncapped (grep has `RECALL_SLICE_TOKEN_CAP`; lines does not), and the recall result's
   tool is in `EXEMPT_TOOLS` so L0 can never re-fold it. One `recall {code}` permanently
   undoes the gate's savings — contradicts DESIGN §6a "recall can't itself re-flood".

6. **Error-lexicon false negatives** (`policy/ledger.ts:63-69`). Regex misses lowercase
   `failed`/`failure` (vitest/jest summaries), `fatal`, `npm ERR!`, `Segmentation fault`,
   `denied`, `✗`. A test-runner wall with `isError=false` folds at the normal threshold and
   the failure line drops out of the pointer — the exact rtk failure mode this project exists
   to prevent.

7. **No master kill switch.** Keel folding + tools activate unconditionally on load; only L0
   has an env gate. Add `CONTEXTFOLD=0`-style disable so a live incident doesn't require
   unlinking the extension.

## Major (soon after)

- **Model digests bypass budget accounting** (`store.ts:374,454-459`): floor proves budget in
  deterministic-digest units, lowering swaps in longer model digests un-recosted — wire can
  exceed cap while telemetry reads under. Also `cleanDigest` only strips a *leading* fold tag:
  a weak model can inject phantom `{#xxxxxx FOLDED}` handles into context. (Model path is
  currently off in prod, so major not blocking.)
- **Group summaries advertise unfoldable codes** (`digest.ts:163-186` vs `store.ts:261-317`):
  `foldCode(group.id)` is in no lookup table — L4's "reversible" claim is false in practice.
- **Entity-reachability tier is dead code** (`policy/edges.ts:21-24`): `messagePrefix` slices
  at the first colon → `a:`/`r:`/`u:` chain the whole session into one reachable component
  (verified: 40/40 marked reachable with zero shared entities). Ranking silently degrades to
  risk+ACT-R only.
- **`tailTarget` 20k unclamped vs budget** (`store.ts:44`): any context window under ~27k
  protects everything → nothing ever folds. Clamp tail against budget.
- **grep/lines numbering mismatch** (`store.ts:590-599` vs `301-305`): grep reports
  `fullOutputPath` line numbers, `lines=` slices the spool — follow-up slices silently wrong
  when bash truncated in-band output.
- **Multi-session process staleness** (`index.ts:106-108`): `restored` latches once and the
  registry is never cleared on session switch — cross-session code collisions possible.
- **Silent empty catches** (`index.ts:116-117,144-146`): gate/restore failures invisible even
  with `CONTEXTFOLD_DEBUG=1`. One stderr line each.
- **Semicolon-less JS/TS skeleton drops interface members** (`skeletonize.ts:393-397,535-542`,
  reproduced): brace-depth desync elides declared contract members from the skeleton.

## Experiment verdicts

- **L0 gate eval (`~/experiments/l0-gate-eval`): the Qwen3.6 default-on decision SURVIVES.**
  Recomputed pooled ratios match RESULTS.md; buried-error effect is huge and near-zero-variance
  (26.7k→4.6-5.2k input tokens, n=3); success checks deterministic; arms leak-proofed. Honest
  framing is "saves ~78-82% where a flood lands, costs 2-6% elsewhere" — the pooled 0.29
  overstates typical savings. Corrections needed in RESULTS.md: the web-fetch task never
  exercised web fetch (pi-web-access SSRF guard refused 127.0.0.1 in 100% of runs; agents used
  curl), and the "112 bash calls" claim matches nothing in the archived traces (max anywhere
  is 13). gpt-5.5 opt-in is the right call but its "recall churn" narrative rests on one noisy
  rep (n=2, 2.6× spread).
- **Phase-3 recall eval: qualitative mechanism yes, headline numbers no.** The
  100%/83%-vs-50%/33% table is one unlogged run; the 83% driver-recall figure is never
  asserted by the test; mid-block fact-planting makes det-fold's 50% structural (L3 digest
  cannot carry a mid-block line) rather than discovered; and the run used Qwen3.5-9B while the
  shipped default is the 4B-MTP (never re-run). Fisher exact on 6 binary facts: p≈0.09-0.12.
  Supports "model digests preserve mid-block identifiers, worth offering" — not the README's
  quantitative framing.
