# context-fold rebuild — implementation plan (2026-07-28)

Implements `docs/HANDOFF_REBUILD_2026-07-28.md`: parity with Evoker's ratified
B/C/A layered compaction, releasable to the Pi community (publishing owner-gated).

## Mode selection

`CONTEXTFOLD_MODE` picks the folding policy. Default **`ladder`** (the rebuild);
`keel` keeps the original continuous per-turn Keel ladder as a documented
legacy/experimental path (the Sol campaign demoted it as a default — kept for
eval comparability, not recommended). `CONTEXTFOLD=0` remains the master kill.

- **ladder** (default): discrete fold events. Between folds, context is
  append-only. Each fold masks stale observations (tool_result + thinking
  blocks outside the protected tail) to their deterministic digests — pointer
  masks with risk-line retention — committed as a prefix-stable **frozen
  layer** (bytes never change again; the existing Stage-2 mechanism, now
  always on in this mode). A deterministic **seed index** is emitted at every
  fold. Zero model calls.
- **keel**: the Phase 1–6 continuous conductor, unchanged. `CONTEXTFOLD_MODEL`
  / `CONTEXTFOLD_COLDNESS` (model digests / model coldness) only apply here —
  in ladder mode a fold's bytes freeze at commit, so a late async model digest
  could never ship; the adapter says so on stderr if both are set.
- The **L0 ingestion gate** is orthogonal and unchanged in both modes
  (`CONTEXTFOLD_L0` allowlist; born-folded pointers; spool; recall/unfold).

## Threshold ladder (defaults mirror the Evoker packet)

| env | default | meaning |
|---|---|---|
| `CONTEXTFOLD_FOLD_AT` | `0.45` | first fold when usage ≥ this fraction of the context window |
| `CONTEXTFOLD_FOLD_STEP` | `0.12` | next fold when usage ≥ post-fold usage + step |
| `CONTEXTFOLD_MAX_LAYERS` | `2` | consolidation: a fold event that would exceed this merges all layer records into one |
| `CONTEXTFOLD_COLD_FOLD_AT` | `0.25` | first-fold threshold when the session has never observed a live cache read (no prefix to protect → fold earlier and more freely) |

Usage fraction prefers provider-reported tokens (`view.reportedTokens`) and
falls back to the chars÷4 estimator. The budget cap (`CONTEXTFOLD_BUDGET_CAP`,
min(200k, fraction × window)) stays as the hard ceiling: over cap → immediate
emergency fold event regardless of the ladder position, and the engine's
existing consolidation loop (break oldest layer, replan) still backstops.

Consolidation divergence, documented not improvised: Evoker's rule bounds
*summary nesting*. Pi-side folds are pointer masks, not summaries — nothing
nests — so consolidation here merges layer *records* (bookkeeping; digest
bytes are unchanged, so the warm prefix is preserved for free). Byte-level
deepening (group digests) stays available to the budget floor only.

## Hard floor (A never automatic)

`session_before_compact` interception, `CONTEXTFOLD_COMPACT`:

- `det` (default): supply Pi a **deterministic compaction summary** rendered
  from the seed index (files, commands, errors, identifiers, first user
  lines, recall codes + spool paths) instead of an LLM summary. No model
  call, no hallucination surface, and the C layer (spool + index + log)
  keeps everything recoverable.
- `native`: leave Pi's own compaction alone.

Headless Pi cannot block for a stop-and-ask, so the "ask" half is advisory:
the status line + a loud stderr advisory recommend `/fold-handoff` + `/new`
when the floor is near (see yellow flag).

## C layer: seed index + span recall

- Spec: `docs/SEED_INDEX_SPEC.md` (shared with Evoker; consumed by `/recall`
  and autojournal). Extractor is pure core (`src/core/index/seed-index.ts`),
  reusing `ledger.categorize` (error lexicon incl. lowercase `failed`,
  `npm ERR!`) and `lexical.extractIdentifiers`.
- Emission: adapter writes/updates `seed-index.jsonl` in the session spool dir
  at every fold event + at `session_before_compact`; also event-sourced as a
  custom entry so resume is consistent.
- Span recall (churn is the measured failure mode): `recall` gains a
  codes-optional `search=<term>` that greps **all** registered spools + the
  index in one call, returning per-code matching lines (capped). Recovering
  identifiers scattered across N pointers costs 1 call, not N.

## Cold detection + reset yellow flag (price-agnostic)

- `CacheTelemetry` gains `everWarm` / `coldStreak`; a turn that should be warm
  (turn > 1, carried context large) with `cacheRead == 0` marks the session
  cold. One-line stderr advisory when cold with large context.
- Yellow flag in input-token equivalents (no dollar prices): warm carry ≈
  0.1 × carried, cold carry ≈ carried, reconstruction ≈
  `CONTEXTFOLD_RECON_TOKENS` (default 18k). `/context-fold` status shows
  payback ("reset pays back in ~N warm turns") and flags: second forced
  compaction, irreducible post-fold context > 50 % window, cold with large
  context, recall churn.

## A layer: opt-in handoff

`/fold-handoff` command: writes a handoff seed to the session directory —
deterministic part first (seed index rendered + open recall codes), optional
model summary only when a model connection is configured, always prefixed
with the degradation warning ("summaries lose detail; the log and index are
the ground truth"). Never fires automatically.

## Verification

- Existing: full vitest suite, `e2e-gate.sh`, `e2e-resume.sh`, `e2e-cache.sh`
  stay green (keel-mode tests pin `CONTEXTFOLD_MODE=keel` where they exercise
  continuous folding).
- New: index-fidelity test (planted mid-tool-output identifiers must appear in
  the emitted index — the summary-boundary probe class); churn guard (span
  search over N planted pointers resolves in 1 call); ladder unit tests
  (threshold crossing, step advance, consolidation merge, cold branch,
  emergency fold at cap).
